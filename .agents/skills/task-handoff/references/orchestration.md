# Task Handoff 主会话编排指南（按需读取）

> **读取边界**：**独立拉起的 `designer` 节点严禁读取本文件**；单会话直出设计模式下，当前会话仅可按需读取第 1 节（选任务前置），跳过第 2 节（Scout 预摸底）。

---

## 1. 选任务前置规则（1A）

收到开放式“推进下一步”类请求时，由主会话（通常为经济模型）先定题，避免高思考 `designer` 横向扫描多个候选任务的源码：

1. **已明确任务时直接跳过**：若用户已指定具体任务 ID、功能目标或需求描述，直接跳过本节。
2. **只读任务源与台账定题**：主会话只读项目任务追踪源（如 `tasks.md` / `spec.md` / Roadmap / Issues）与 `HANDOFF_LEDGER.md`（若存在），整理待办候选简表与前置依赖关系：
   - **依赖明确、存在唯一清晰下一项**：主会话直接锁定该任务并继续推进；
   - **存在多个并列无优先级候选项**：先向用户简短汇报候选简表与推荐项，等用户确认选题后再派发 `designer`。
3. **向 `designer` 传递定题上下文**：在给 `designer` 的 `brief` 中附上**候选简表与定题理由**，要求 `designer` 不再横向扫描其他候选任务源码，仅核验所选任务的前置依赖（若发现依赖未满足或存在阻断冲突，必须立即停步报回用户，严禁硬写）。

---

## 2. 轻量只读预摸底（Scout → Context Pack，2A）

### 启用与跳过条件（避免付两次钱）
- **直接跳过 Scout**：
  - 用户已显式给出具体目标文件或明确的小范围目录；
  - 任务改动面明确很小（如仅涉及 1–2 个已知文件）；
  - 当前为单会话直出设计模式（不拉起独立 `designer` 节点）。
- **启用 Scout**：跨多模块 / 中大型仓库摸底，且即将拉起独立高思考 `designer` 节点、主会话尚未掌握目标文件坐标时启用。

### 三级跨 CLI 降级
1. **首选 · 一次性轻量只读子代理（对防模型漂移红线的有意限定例外）**：
   - 在支持独立只读子代理的环境中（如 Antigravity 的 `research` 子代理配 `flash`），派发 **1 个**一次性只读侦察节点收集坐标简报，不污染主会话施工上下文；
   - **红线边界**：该例外**仅限前置只读坐标导航**，严禁让其参与技术决策、编写执行单或替代高思考 `designer`。
2. **降级 1 · 主会话轻量定位**：
   - 若无独立便宜只读子代理，但当前主会话为经济模型，由主会话用 **≤ 2 轮**定向只读检索（读 `CODEBASE_MAP.md` / `HANDOFF_LEDGER.md` + 少量符号搜索）整理坐标简报。
3. **降级 2 · 单会话直出**：
   - 跳过 Scout，直接按 `SKILL.md` 的低上下文渐进式摸底纪律执行。

### Context Pack 输出约束
- 结构严格参照同目录 [context-templates.md](./context-templates.md) 的 Context Pack 模板；
- **硬上限 ≤ 150 行**：只提供精确坐标（`path:start-end`）、单行符号签名、调用方/`mock` 锚点与精简版本实测输出，**严禁粘贴大段源码**；
- 简报作为坐标线索注入 `designer` 的 `brief`，**不免除 `designer` 对核心代码正确性与改签名调用方完整性的亲自核验**。
