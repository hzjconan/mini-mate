# Task Handoff Drafting, Revision & Freeze

收到“推进下一步”、起草任务执行单、按审稿意见修订执行单或拍板定稿锁版时，按本规范执行。核心目标：由高思考模型一次性把摸底、技术决策、接口契约与坑点想透，产出**脱离当前对话也能让轻模型零歧义照图施工**的单源真相执行单。

## 第 0 步：项目上下文发现（零配置可用，有约定优先继承）

执行任何操作前，先只读检查目标仓库根目录的项目规范文件（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md`），提取并继承：
- **项目红线**：禁读/禁改目录、禁运行副作用命令、只读基线保护等；
- **执行单路径**：默认 `docs/handoffs/<task>-handoff.md`（若规范另有约定从其约定）；
- **任务追踪源**：如 `specs/*/tasks.md`、`TODO.md`、Roadmap、Issues（无则以用户描述为准）；
- **验收门禁与附加产出**：约定的测试/lint/类型检查/构建命令及需同步文档；
- **项目架构地图（可选）**：**只认两处**——第 0 步识别到的项目规范文件显式声明路径，其次默认 `docs/CODEBASE_MAP.md`（**严禁自动探测读取老仓库的 `ARCHITECTURE.md`**）；
- **上下文台账（可选）**：优先项目规范文件声明路径，其次 `docs/HANDOFF_LEDGER.md`；若项目规范文件声明 **`上下文台账：不启用`**，静默跳过且不输出超阈值提示；
- **可选符号大纲命令**：项目规范文件显式声明则优先复用，未声明不依赖外部工具；
- **首选模型配置（纯可选）**：未指定时默认同系列 `High` 档位（不默认升 `XHigh`）。

> **按需参考指针（零常驻展开）**
> - 主会话收到开放式“推进下一步”或需对跨模块大仓做轻量预摸底时，读取 [references/orchestration.md](./references/orchestration.md)（**独立拉起的 `designer` 节点严禁读取；单会话直出模式仅可读 1A 选任务部分，跳过 2A Scout 部分**）；
> - 仅当用户显式要求“初始化本项目上下文索引”时，读取 [references/bootstrap-migration.md](./references/bootstrap-migration.md) 执行；**常规起草/修订/定稿任务严禁读取该文件**。

## 绝对红线

- 完整继承第 0 步全部项目红线；
- **设计阶段只写执行单**：仅创建或更新目标执行单文件，严禁改动业务代码、测试、配置或历史产物；
- **未经用户明确同意不得开工**；写完直接汇报给用户，不做内部二次审稿。

## 派发与生命周期（高思考设计 + 跨 CLI 降级）

1. **首选 · 单节点高思考设计师（支持精确模型名/思考等级的单节点工具，如 Antigravity 的 `swarm`）**：
   - **选型优先级（严禁凭猜测跨系列选型）**：`用户本次指定 > 项目规范指定 > 默认同系列 High`。无法确认当前系列时，先不传 `model` 拉起并立即 `status` 核实系列，再切同系列 `*-high`；
   - 主会话与目标设计模型不一致且环境提供精确模型单节点工具时，**必须先 `swarm(action="models")` 再 `swarm(action="add", name="designer", workspace="inherit", model=...)`**，仅拉起 1 个节点；**严禁**用粗粒度子代理（如 `invoke_subagent(pro)`）替代高思考 `designer`。
   - **Scout 有意限定例外**：主会话在拉起 `designer` **之前**按 `orchestration.md` 派发 1 个一次性只读 `research/flash` 收集坐标简报（Context Pack），是对上述防漂移红线的**有意限定例外**，仅限前置坐标导航，严禁参与设计决策或替代 `designer`。
   - **`brief` 必须明文包含**：
     1. 本 `SKILL.md` 与同目录 `references/handoff-template.md` 的实际加载路径，要求严格执行；
     2. 本次目标范围（主会话已定题时附**候选任务简表与定题理由**；若有 Scout 产出的 Context Pack 与已发现 Map/Ledger 路径一并附上）；
     3. 只读摸底红线与项目红线（仅允许写目标执行单）；
     4. 汇报要求（执行单路径、核心发现与待拍板决策清单）。
   - **已定题核验**：主会话已定题时，`designer` 不再横向扫描其他候选源码，仅核验所选任务前置依赖——**依赖未满足或存在阻断冲突时必须立即停步报回用户，严禁硬写**。
   - **休眠承接修订**：初稿完成后不 `kill` `designer`（`waiting` 不耗额度），审稿意见直接转发 `@designer` 原地修订并清理旧表述残影。
   - **默认定稿与回收硬规则（含存量旧草稿守卫）**：
     - **当用户全按推荐项拍板且下篇正文无待折叠条件分支时，强制由主会话直接更新顶部元信息（`状态：已拍板定稿（待实施）` 与拍板决议摘要）落盘定稿，严禁为此再次唤醒 `@designer`**；
     - 若用户选非推荐项、提出需求微调、或该单属升级前遗留的旧格式在途草稿（下篇仍含待折叠条件分支），仍通知 `@designer` 按差量原地折叠定稿并核查全文一致性；
     - 定稿落盘后（或取消时）立刻 `kill` `designer`，核验 `git status` 后由主会话施工。
2. **降级 · 当前会话直接起草**：主会话已满足目标模型/思考等级，或 CLI 不支持精确模型单节点工具时直接在当前会话执行（工具受限降级须在汇报中注明）。

## 低上下文渐进式摸底与完整性核验纪律（严禁凭记忆编造）

1. **上下文承接防膨胀**：
   - 存在 `HANDOFF_LEDGER.md` 时，以台账为种子线索承接遗留待办与已知陷阱，不遍历 `docs/handoffs/`；
   - 无台账时，**按任务追踪源依赖定位全部直接上游执行单（不限数）**，但每份仅定向读取「遗留待办 / 已知限制 / 环境陷阱 / 复审闭环」节，严禁通读全文。
2. **Map / Ledger 种子线索原则**：`CODEBASE_MAP.md` 与 `HANDOFF_LEDGER.md` 仅为冷启动导航与种子线索，与真实代码冲突时一律以代码为准，并在执行单 §8 标注需同步条目。
3. **零信任扩展到“正确性 + 完整性”**：无论是否收到 Context Pack，凡直接修改的文件，以及**所有改签名、改数据结构或改公共行为的符号**，`designer` 必须亲自读取真实源码切片核实 `file:line`（正确性），并**亲自执行一次全仓调用方与测试 `mock`/`patch` 搜索（完整性）**，不得以 Context Pack 列表为全集。
4. **三层漏斗读法与跨平台符号骨架**：
   - **L1 全局定位**：读 `CODEBASE_MAP.md`（若有）或限深度目录列表；
   - **L2 符号定位与骨架（四级零依赖降级）**：项目规范声明的大纲命令/LSP → `CLI 原生只读搜索工具（三端通用）> rg > git grep > grep -rnE（类 Unix/Git Bash）或 Select-String（Windows PowerShell）` → 语法不适用时回退 `CODEBASE_MAP.md` + 局部切片；骨架仅作外围接口参考与定位，核心契约必进 L3 读源码核实；
   - **L3 分级精读**：直接修改文件精读相关区间（≤ 200 行可读全文）；外围调用方只看签名与 `-C 3`；既有测试优先读 fixture 与命中被改符号用例片段。
5. **分阶段同轮并行读（跨 CLI 降级）**：先完成第 0 步提禁读红线 → Stage 1 并行定位 → 筛选最小切片 → Stage 2 并行精读（严禁未定位前盲目并行读全文）；不支持并发的工具退化为单条只读复合命令或按优先级串行。
6. **高噪与 lockfile 规则**：禁通读构建/压缩产物与大二进制快照；**对 lockfile 严禁全文读，但允许按目标包名定向 grep 核查版本与来源**；第三方依赖/环境实测须定向查询目标包或截断输出。

## 执行单必备结构（人机分层、单源真相、默认推荐态终稿）

标准骨架见 [references/handoff-template.md](./references/handoff-template.md)（纯文档/验证类任务可将接口契约改为文档结构与事实口径契约）。
- **下篇一律按推荐项写成无条件分支终态**：非推荐备选项**仅在 §2 决策清单中写明“若选该项需对下篇调整的差量”**，严禁在下篇正文穿插“若选 B 则…/按决策 X 折叠”类条件分支；
- **上篇（面向决策，精简）**：① 顶部元信息、Git/依赖基线与红线声明；② 任务目标与选择理由（已由主会话定题时引用定题理由 1–2 行并注明前置依赖已核验即可）；③ 待拍板决策清单（编号选项、推荐项与备选差量）；
- **下篇（面向轻模型零歧义施工）**：④ 现状锚点（`path:line`）与环境实测陷阱；⑤ 文件改动表与明确不做清单（Non-Goals）；⑥ 精确接口与行为契约（完整签名、复用锚点、边界/异常/退出码、既有调用方与 mock 兼容性）；⑦ 自底向上原子化施工步骤（每步附最小验证命令）；⑧ 确定性测试矩阵（正例/边界/异常反例/兼容回归，写死强断言底线）与完整门禁命令；⑨ 附加产出要求（含按需同步 `CODEBASE_MAP.md`）；⑩ 实施方偏差止损规则（可自决微调 vs 必须立即停工上报）。

## 汇报给用户的格式

1. **执行单链接**（`file://`），并明文标注设计通道（单节点 `designer` / 当前会话直出）、精确模型名与思考等级；
2. **核心说明**：初稿列任务目标与最关键技术风险；修订列按意见改动要点与异议证据；定稿确认已写死决议、回收 `designer` 且 `git status` 干净；
3. **待拍板决策清单**（编号列出，便于回复 `1A 2A ...` 或转外部评审）；
4. 初稿/修订阶段明确说明**尚未改动任何代码，等待确认后再定稿开工**；若未配置 `上下文台账：不启用`、无 `HANDOFF_LEDGER.md` 且 `docs/handoffs/` 已有 ≥ 5 份 `.md` 文件，文末附 1 行温和建议（可回复初始化索引，或在项目规范文件中声明 `上下文台账：不启用` 关闭提示）。
