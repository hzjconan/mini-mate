# 独立只读审查员协议（Reviewer Protocol）

本协议为 `task-review-loop` 的独立审查员（以及「降级 2 · 无子代理能力时实施方自查」）的唯一权威执行标准。

## 1. 只读红线、意见分级与双重审查视角

- **零副作用只读红线**：仅允许只读读取、只读查询与无副作用检查（只读单测、lint、类型检查等）。**严禁修改任何文件，严禁运行写盘或改 Git 状态的命令（审查员绝不运行 `git add` / `git write-tree`）**，并完整遵守 `brief` 中列出的项目红线。
- **意见分级定义**：
  - **阻断项**：功能/逻辑 bug、违背定稿执行单/需求/项目原则、执行单自身遗漏或假设有误导致的真实缺陷、跨模块漏接或只读保护破坏、测试假阳性或缺失关键反例、实测口径失真或不可追溯、隔离性/安全性被破坏。
  - **非阻断建议**：风格微调、可读性改进、改动面较大可延后到后续任务的优化。
- **双重审查视角**：
  1. **对照基线查落地**：核查是否完整落实定稿执行单（或任务需求）的改动范围、不做清单、接口契约、测试矩阵与文档更新点；
  2. **跳出基线找真实工程缺陷**：严禁盲信执行单假设；主动核查跨模块调用方、第三方库真实行为与端到端业务路径——**即使执行单自身写漏或假设有误，只要构成真实 bug 或风险，同样判为阻断项**。

## 2. 上下文导航与执行单读取边界

- **Map / Ledger 仅作种子线索**：若 `brief` 提供 `CODEBASE_MAP.md` 或 `HANDOFF_LEDGER.md`，仅用作冷启动入口/陷阱线索，**严禁替代对被改符号的独立全仓调用方搜索**；与真实代码冲突时一律以代码为准，并将“Map/Ledger 过期”列为非阻断建议。
- **执行单必读与可跳过区**：存在执行单时，**顶部元信息、拍板决议摘要、红线声明、任务目标与质量底线以及下篇施工契约（改动范围、不做清单、接口契约、测试矩阵、附加产出）全部必读**；仅允许跳过纯痛点背景叙述与文末 Q&A 讨论附录。

## 3. 每轮必做：只读核验整树快照 `T_CUR` 新鲜度

收到实施方传入的本轮整树快照 `T_CUR` 后，严禁盲信，必须先只读核验其与当前工作区一致（所有变量名使用合法 Shell 变量 `$T_CUR` / `$T_PREV`，`<tree>:<path>` 必须加花括号与双引号 `"${T_CUR}:<f>"` 防 `zsh` `:u` 等修饰符报错）：

1. **核验已跟踪文件与未跟踪列表**：运行 `git -c core.quotePath=false diff --name-status "$T_CUR"`，并与 `git -c core.quotePath=false ls-files --others --exclude-standard`（辅以 `git -c core.quotePath=false status --porcelain -uall` 核对暂存/工作区状态）比对——`diff --name-status` 会把未跟踪文件输出为 `D\t<path>`，该原始路径集合必须与 `ls-files --others --exclude-standard` **逐行一一对应**；除此之外只要出现任何已跟踪文件变动、或多出/缺少未跟踪条目，即判 `T_CUR` 过期，**立即退回要求实施方重算**。
2. **核验未跟踪文件内容**：对未跟踪列表中的每个文件 `<f>`，只读比对 `git hash-object -- "<f>"` 与 `git rev-parse "${T_CUR}:<f>"`；任一失败或哈希不等即判 `T_CUR` 过期并退回。

> 若因降级模式未传入 `T_CUR`，回退为常规 `git -c core.quotePath=false status --porcelain -uall` 与 `git diff` 核查。

## 4. Round 1 分级零信任复验与高效读法

- **统一整树 Diff**：验完 `T_CUR` 新鲜度后，运行 `git -c core.quotePath=false diff --stat HEAD "$T_CUR"` 与 `git diff HEAD "$T_CUR" -- <files>`（无初始提交的新仓用零写盘的 `EMPTY_TREE="$(git hash-object -t tree /dev/null)"` 替代 `HEAD`，PowerShell 用 `@() | git hash-object -t tree --stdin`），未跟踪新文件内容直接在同份 diff 中可见。
- **高噪差异化处理（严防误伤攻击面 #2/#4/#6）**：
  - **快照 / golden 文件严禁跳过**：凡出现在 `--stat` 中，**必须查看其定向 diff**，排查“改测试预期让假修复变绿”；
  - **lockfile 只禁整份倾倒**：出现在 `--stat` 中时，有执行单则对照改动范围表（未申报即判阻断）；**无执行单时对照用户任务描述判断（变动无法合理解释即判阻断）**；属合理变动时须定向 grep 变动的包名、版本与下载源（如 `resolved` / registry 行）。
- **大文件可执行切片规则**：中小改动文件（≤ 250 行）读全文；大文件（> 250 行）除精读受影响函数/类、import/初始化与相关 fixture 外，**必须在文件内定向 grep 每个被改符号、被改字段与共享状态的全部引用并读取引用处上下文**；跨模块调用方全仓搜索遵循三端降级链（`CLI 原生只读工具 > rg > git grep > grep -rnE / Select-String`）并看 `-C 3`。
- **静默复跑测试与防假阳性核验**：独立复跑只读测试/lint/类型检查优先用摘要参数，但**必须保留最终计数汇总行并开启跳过/预期失败原因输出**（如 pytest 用 `-q -rsxX --tb=short`，其他框架用等价参数），**核对新增用例实际被收集执行且实测数与测试矩阵一致**；新增用例被 skip/xfail 或未收集即判阻断（**除非定稿执行单测试矩阵或项目规范已明文写明该用例的跳过条件，如平台/环境限定用例**）。Round 1 优先复跑新增/受影响单测 + 关键回归 + lint/类型检查。
- **分阶段并行只读（跨 CLI 降级）**：支持单轮多工具并发时压缩至 3–4 轮（第 1 轮并行读协议 + 执行单必读区 + Map/Ledger + `T_CUR` 新鲜度与 `HEAD..T_CUR --stat` → 第 2 轮定向 diff + 改动/全引用切片 + 全仓搜调用方 → 第 3 轮精简复跑测试 → 第 4 轮出报告）；不支持并发则安全降级为无副作用复合只读命令或按优先级串行。

## 5. Round 2+ 精确增量复审、防漂移与终轮全量兜底

- **聚焦与防漂移**：重点复核 ① 上轮阻断项是否真正根治且有确定性回归测试；② 实施方异议证据是否成立；③ 本轮修复是否引入新回归（含文档同步）。**严禁对未改动代码反复冒出新的低优先级风格意见卡通过**（但发现遗漏的真实严重缺陷仍应阻断）。
- **精确增量审查**：验完 `T_CUR` 新鲜度后，运行只读 `git -c core.quotePath=false diff --name-status "$T_PREV" "$T_CUR"` 捕获全部真实增量改动面（含未申报改动与等长改写），再用 `git diff "$T_PREV" "$T_CUR" -- <files>` 查看精确增量，不重复倾倒 Round 1 已审内容。
- **改签名全仓重搜 + 终轮全量门禁兜底**：每轮若修复修改了符号签名或对外行为，必须重新全仓搜索该符号的全部调用方（含 Round 1 改动文件）；**准备判定「通过（阻断项 = 0）」的那一轮，必须独立、精简地复跑一次项目全量验收门禁**（若全量套件确因耗时过长不宜由审查员重跑，须在报告中明文注明原因，并逐字核对实施方基于最终快照 `T_CUR` 的全量实测输出）。

## 6. 6 类高频攻击面必查与统一输出格式

逐项过筛以下 6 类攻击面（分栈细项按需参阅同目录 [checklists.md](./checklists.md)）：
1. **跨模块接线与复用一致性**：新工厂/辅助函数/配置是否接入全部生产入口？同类入口是否漏改或重复造轮子？
2. **第三方依赖与并发/资源生命周期陷阱**：只读实测或读源码确认库行为；排查阻塞事件循环、竞态、连接/句柄/临时文件泄漏及权限暴露面。
3. **异常路径与边界输入**：空值/极值/坏文件/链路中途抛错时状态是否完整回滚清理？杜绝静默吞错或静默降级建脏状态。
4. **测试真实性与断言强度**：杜绝假阳性、弱断言、过度 mock 或非确定性；正反例与兼容回归齐备。
5. **实测数字与文档口径真实性**：测试数、耗时、统计数与最终代码最后一次实测输出逐字一致；区分实机联调与 Mock 模拟；清理旧表述。
6. **只读保护与仓库干净度**：只读基线/锁文件完好；无残留临时文件/空目录/调试打印；未提前勾选任务追踪项或提前 commit。

**统一输出格式**：**结论（通过 / 需修改）→ 阻断项（带 `file:line` 与复现/反证依据）→ 非阻断建议 → 逐项核查证据**。无问题的攻击面用 **1 行简明证据**带过，但**每行必须包含具体执行的命令或核验到的 `file:line`，严禁只写“无问题”或“已检查通过”**。
