# Feature Specification: M3 记忆、离线与预置短句

**Feature Branch**: `004-m3-memory-offline`

**Created**: 2026-11-20

**Status**: Draft

**Input**: `docs/tech-selection.md` v3.1 第 4.6、4.8、4.9 节与第 7 章 M3："会话记忆 + 离线模式 + 预置短句 +（可选）本地快速指令"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 它记得我 (Priority: P1)

我昨天告诉它我养了一只叫"团子"的猫、最近在准备考试；今天再打开 App，它会自然地提起"团子今天乖吗？""考试准备得怎么样了？"。它也记得我最近几天心情不太好。

**Why this priority**：陪伴感依赖连续性；没有跨会话记忆，每次都像第一次见面。

**Independent Test**：第一次会话说出几条个人信息，关闭 App；第二次会话询问相关问题，检查回答。

**Acceptance Scenarios**:

1. **Given** 上次会话中我说过"我养了一只猫叫团子"，**When** 新会话中我问"你还记得我的猫叫什么吗"，**Then** 它回答"团子"。
2. **Given** 上次会话结束，**When** 会话结束后 1 分钟内，**Then** 本地已生成该会话的摘要与新抽取的长期事实。
3. **Given** 过去 3 次会话中我的语气多为 `tired` / `sad`，**When** 新会话开始，**Then** 它的开场回应带有关切（来自情绪趋势）。
4. **Given** 某条事实已经过时（我说"我已经考完试了"），**When** 会话结束后更新记忆，**Then** 旧事实被更新或标记为过时，不再被当作现状提起。
5. **Given** 记忆累积很多，**When** 建立新会话，**Then** 注入内容不超过预算（人格 ≤ 800、事实 ≤ 500、摘要 ≤ 500 token 估算）。

---

### User Story 2 - 断网时它不会傻掉 (Priority: P1)

网络断了，它不会卡住不动。它会告诉我"网好像断了"，但我说"笑一个""转个圈""你好"这类话时它仍然会照做和回应；网络恢复后自动回到正常对话。

**Why this priority**：tech-selection 2.2 的硬约束"必须有断网 / 弱网降级路径"。

**Independent Test**：开启飞行模式（保留 Wi-Fi 关闭），按 quickstart 测试本地指令。

**Acceptance Scenarios**:

1. **Given** 正常对话中网络断开，**When** 重连 3 次失败，**Then** 形象做出"困惑"姿态并用系统语音说一句预置提示，进入离线模式。
2. **Given** 离线模式，**When** 我说"转个圈"，**Then** 形象转圈并说一句预置短句。
3. **Given** 离线模式，**When** 我说一句无法匹配的话（如"今天天气怎么样"），**Then** 它用预置话术表示现在网不好、回头再聊，不胡乱回答。
4. **Given** 离线模式，**When** 网络恢复，**Then** 10 秒内自动重建实时会话，回到在线模式，并有一个"回来了"的反应。

---

### User Story 3 - 熟悉的短句随叫随到 (Priority: P2)

它打招呼、附和（"嗯嗯""对呀"）、等待时说的"嗯…我想想"，都和它平时回答是同一个声音，而且几乎没有延迟。它不会每句话前都说"我想想"，只在需要比较久的时候才说。

**Why this priority**：降低体感延迟、保持音色一致（tech-selection 4.6、4.8）。

**Independent Test**：在调试面板逐条播放预合成短句，检查音色；在对话中统计垫场短句触发率。

**Acceptance Scenarios**:

1. **Given** 首次安装或更换音色，**When** 在线时进入设置 > 预合成短句 > 生成，**Then** 全部短句用当前 TTS 音色与对应情绪合成并保存到本地。
2. **Given** 预合成完成，**When** 播放任一短句，**Then** 从触发到出声 < 50 ms。
3. **Given** 一轮对话首个文字在 1.2 秒内到达，**When** 观察，**Then** 不播放垫场短句。
4. **Given** 一轮对话超过 1.2 秒仍无首个文字，**When** 观察，**Then** 播放一句垫场短句；实质回答到达后在该短句结束时自然衔接。

---

### User Story 4 - 我能查看和删除它记住的东西 (Priority: P2)

我可以在设置里看到它记住了关于我的哪些事，删除不想让它记住的条目，或者一键清空所有记忆与对话记录。

**Why this priority**：记忆涉及个人隐私；自用也需要可控。

**Independent Test**：在设置中查看、删除一条事实，再开新会话确认不再被提起；一键清空后数据库为空。

**Acceptance Scenarios**:

1. **Given** 已有若干长期事实，**When** 打开设置 > 记忆，**Then** 按类别列出全部事实及来源时间。
2. **Given** 删除"我养了一只猫叫团子"，**When** 新会话中问"我的猫叫什么"，**Then** 它不知道。
3. **Given** 点击"清空全部记忆与对话"并确认，**When** 完成，**Then** 本地对话记录、摘要、事实全部删除。

---

### User Story 5 - 简单指令更快 (Priority: P3，可选)

在线时，我说"笑一个""转个圈"，它几乎立刻就做，不需要等云端回答。

**Why this priority**：可选优化，取决于 003 中闭集指令经云端的体感延迟。

**Independent Test**：在线时说 10 次闭集指令，测量从说完到动作开始的时间。

**Acceptance Scenarios**:

1. **Given** 本地快速指令已开启，**When** 我说"转个圈"，**Then** 说完后 500 ms 内开始转圈。
2. **Given** 本地已执行动作，**When** 云端回答中也包含 `<act:spin>`，**Then** 不重复执行。

---

### Edge Cases

- 会话中途 App 被杀：已完成的轮次 MUST 已落盘；下次启动时为未摘要的会话补做摘要。
- 摘要请求失败：保留原始轮次，下次在线时重试；不阻塞新会话。
- 抽取出的事实与已有事实矛盾：以新的为准，旧的标记为过时并保留来源。
- 用户在对话中说"别记这个"/"忘掉刚才说的"：本轮不抽取事实。[NEEDS CLARIFICATION: 是否需要支持语音指令让它"忘掉"某事？默认只在本轮跳过抽取]
- 离线时 `SpeechTranscriber` 中文资源未下载（001 探测结果）：离线模式只能响应手势与表情，并提示。
- 预合成短句与当前音色不一致（换了厂商或音色）：标记为失效，在线时提示重新生成；失效期间回退到云端实时合成或不播放。
- 会话轮次超过约 20 轮：客户端生成中间摘要并重建会话，用户无感知。

## Requirements *(mandatory)*

### Functional Requirements

**记忆**

- **FR-001**：每轮对话（用户转写、用户语气、助手文字、时间）MUST 在该轮结束时持久化到本地。
- **FR-002**：会话结束后 MUST 异步生成摘要并抽取 / 更新长期事实；失败时可重试，不阻塞对话。
- **FR-003**：建立会话时 MUST 由 `SessionContextBuilder` 按预算组装人格、长期事实、最近摘要与情绪趋势（contracts/session-context.md）。
- **FR-004**：会话内轮次超过阈值（默认 20 轮）MUST 生成中间摘要并重建会话；断线重连时 MUST 用同样方式重建上下文。
- **FR-005**：长期事实 MUST 有类别、内容、来源会话、创建时间、最近确认时间与是否过时；矛盾时新事实覆盖旧事实。
- **FR-006**：若实时接口不提供用户转写（003 V7），MUST 使用端侧 `SpeechTranscriber` 并行转写用于记忆。
- **FR-007**：所有记忆数据只存本地，MUST NOT 上传到除对话所需之外的任何服务；摘要与抽取请求只发送必要的会话文本。

**记忆管理**

- **FR-008**：设置中 MUST 可以查看、删除单条事实，并一键清空全部记忆与对话记录（需二次确认）。

**离线**

- **FR-009**：连续重连 3 次失败或系统报告无网络时 MUST 切换到 `OfflineConversationEngine`；网络恢复后 MUST 在 10 秒内自动切回。
- **FR-010**：离线模式 MUST 用端侧 `SpeechTranscriber` 转写，经意图匹配执行动作并播放预置话术；无法匹配时播放"网不好"类话术。
- **FR-011**：离线模式下的语音输出 MUST 优先使用预合成短句；无对应短句时使用 `AVSpeechSynthesizer`。
- **FR-012**：离线模式 MUST 沿用 003 的收音闸门、回声消除与打断。

**预合成短句与垫场**

- **FR-013**：App MUST 维护一份预置短句清单（问候、附和、垫场、离线提示、动作配话），每条带情绪；可在线一次性用当前音色批量合成并缓存。
- **FR-014**：每条缓存 MUST 记录合成时的厂商、音色与清单版本；任一不匹配即视为失效。
- **FR-015**：垫场短句 MUST 只在首个文字超过阈值（默认 1.2 s）未到达时播放；同一会话中两次垫场之间至少间隔 3 轮。
- **FR-016**：垫场短句播放中实质回答到达时，MUST 在短句播完后再开始回答，二者之间间隔 < 150 ms。

**本地快速指令（可选）**

- **FR-017**：开启时，在线模式下端侧转写与实时会话并行；命中闭集指令立即执行动作，并在本轮内对云端返回的同一动作去重。

### Key Entities

- **ConversationSession**：一次会话（开始 / 结束时间、厂商、是否已摘要）。
- **Turn**：一轮对话（用户转写、用户语气、助手文字、助手情绪序列、时间、TurnMetrics 摘要）。
- **SessionSummary**：一次会话或一段轮次的摘要文本。
- **MemoryFact**：一条长期事实（类别、内容、来源、时间、是否过时）。
- **MoodTrend**：最近若干次会话的用户语气分布（由 Turn 统计得出，不单独存储）。
- **PresetPhrase**：一条预置短句（ID、类别、文字、情绪）及其缓存音频。
- **OfflineIntent**：一个离线可识别的意图（示例说法、对应动作、回应短句类别）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：准备 10 条个人信息分散在 3 次会话中说出；第 4 次会话逐一提问，正确回忆 ≥ 8 条。
- **SC-002**：会话结束后摘要与事实抽取在 60 秒内完成（在线）。
- **SC-003**：单次会话注入内容的估算 token 数不超过预算（FR-003），有测试覆盖。
- **SC-004**：离线模式下 10 条闭集指令（每种说法变体至少 2 种）正确响应 ≥ 8 条；无法匹配的话 0 次胡乱回答。
- **SC-005**：网络恢复到回到在线模式 ≤ 10 秒。
- **SC-006**：预合成短句播放延迟 < 50 ms；与在线回答主观判断为同一声音。
- **SC-007**：20 轮在线对话中垫场短句触发次数与"首个文字 > 1.2 s"的轮次一致，且没有连续两轮触发。
- **SC-008**：删除事实后新会话中不再提起；清空后本地数据库中会话、轮次、摘要、事实记录数均为 0。
- **SC-009**（可选，US5）：本地快速指令从说完到动作开始 p50 < 500 ms。

## Assumptions

- 摘要与事实抽取使用与对话相同厂商的文本模型（非实时接口），按次调用。
- 只有一个用户，记忆不区分说话人。
- 情绪趋势只统计最近 3 次会话的 `<user>` 标签。
- 预置短句清单初版约 40 条，由开发者编写，后续可增补。
- 离线意图集合与 002 的 `ActionTag` 对应，外加"打招呼""再见""夸奖"三类。
